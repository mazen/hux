# Generic tools have one interface and swappable Services; hux ships only web search and page reading

A tool can have one stable typed interface with swappable Services behind it. Roles are granted the tool; the Service that does the work can be switched or added by the Member: a built-in adapter, a Wasm Plugin implementing the tool's WIT interface, or an MCP server's tool mapped onto it (ADR 0009). Each tool has an ordered fallback list of Services. hux ships only the two truly general tools, `web_search` and `web_fetch`; weather, maps, news and the like are ordinary extensions a Member adds, and they may use the same pattern. `web_fetch` works out of the box through the Gateway's own fetch. `web_search` uses the search built into the Member's Model endpoint when it has one (Anthropic, OpenAI, OpenRouter, Gemini); Wikipedia and DuckDuckGo instant answers always work for facts; otherwise the first open-web question gets one plain offer to add a free key, Tavily first (no card), then Exa, with Brave as a paid option. Members add other Services (Kagi, Mojeek, Marginalia, their own SearXNG) by asking. Findings are in `docs/research/tool-providers.md`.

We chose an interface with swappable Services over one tool per vendor so Roles, Skills and Routines never depend on which vendor a household uses, and over a single hard-wired vendor so hux works with no setup. We kept domain tools such as weather out of core because not every household needs them and the existing extension mechanisms fit them. We rejected a keyless general web-search default: bundling SearXNG or scraping DuckDuckGo or Google breaks those engines' terms, and every compliant web-search API needs a key, so hux reuses the Model endpoint's search or offers a key at first use instead.

## Consequences

- A Service sees query text, so each Service gets a Member-set Trust level like a Model endpoint (ADR 0006), defaulting to Public; the Gateway checks a query's Labels against it before sending, and falls back, rewrites or asks. Results come back labelled as web content.
- A Model endpoint's built-in search is a Service with that endpoint's Trust level: its vendor sees the query, so the Gateway sends it as a separate request carrying only the query, after the Label check. The vendor's display terms come with it (visible citations; Gemini's Search Suggestions shown unmodified to the Member who asked).
- Each Service declares its hosts, secret handle, rate limit, cache rules and attribution; its key lives in the vault and its hosts in its own egress allowlist. Answers name the Service and carry its attribution.
- Keyless Services identify hux honestly and cache, and the default list is data the project can update without a release.
